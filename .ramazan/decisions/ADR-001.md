# ADR-001

## Decision
Adopt a Modular Multi-Agent Orchestration Architecture with Deterministic State Management and Non-LLM Verification Gates.

## Context
Autonomous software development using a single LLM prompt fails due to hallucination, lack of test verification, state drift, and context pollution. The system requires structured delegation, strict code review, real test verification, and auditability.

## Alternatives
- Single Monolithic Prompt Agent (e.g. standard chatbot prompt)
- Pure Autonomous Loop without Test Gate (e.g. unconstrained AutoGPT)
- Deterministic State + Multi-Agent Role Separation (Chosen)

## Reason
1. Separating roles (Orchestrator, Architect, Worker, Reviewer, Test Engine) prevents single-point failure and confirmation bias.
2. An objective Test Engine guarantees that only code passing real tests proceeds to review and commit.
3. Deterministic `state.json` and task files prevent state corruption.
4. Circuit Breakers protect against infinite loops and token budget burnout.

## Consequences
- Every feature must be broken down into discrete tasks with measurable acceptance criteria.
- Tasks cannot be marked completed without passing tests and structured reviewer approval.
- Slightly higher token latency for initial planning, but zero unverified hallucinations reaching codebase.
