# ADR-004

## Decision
Enforce Strict Task Scope with Explicit Test Suite Exemption and Isolation of Non-Core Artifacts.

## Context
Sections 14, 20, 25, 34, and 35 of the RAMAZAN AI specification require that worker agents modify only files declared in `task.files`. During earlier development, mobile game demonstration files (`monkey_game.html` and `cops_robbers_game.html`) were generated directly in the repository root outside structured task scopes, violating architectural boundaries.

Furthermore, autonomous worker agents must be able to write automated tests for their implementations without requiring architects to pre-declare every test file path in advance.

## Alternatives
- Allow unconstrained filesystem writes by workers across the repository.
- Require all test file paths to be explicitly declared in `task.files` prior to execution.
- Strict task scope for production source code with an automated exemption for verified test paths (`tests/*`, `*_test.py`, `*.spec.ts`) and zero untracked artifacts at root (Chosen).

## Reason
1. Prohibiting out-of-scope production modifications prevents ripple-effect bugs, accidental file corruption, and unauthorized file generation.
2. Exempting test paths enables workers to practice Test-Driven Development (TDD) and satisfy acceptance criteria autonomously.
3. Attempted violations raise `ScopeViolationError` immediately before any execution step, triggering atomic snapshot rollback and preventing state transition to `TESTING`.
4. Demonstration mobile games are packaged inside `ramazan.ui.games` as clean Python constants to preserve UI preview capabilities without leaving loose HTML artifacts in the git repository.

## Consequences
- Every worker execution passes through `WorkerAgent.check_scope_violation()` before writing files.
- `git ls-files | grep -E '\.html$'` remains completely clean and free of out-of-scope files.
- Unauthorized file creation attempts are caught and logged under `.ramazan/logs/`.
